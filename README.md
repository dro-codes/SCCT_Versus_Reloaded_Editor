# RE+ (Reloaded Editor Plus)

RE+ is an unofficial patch for the **Splinter Cell: Chaos Theory Versus** map editor. It works with the stock game and with [Enhanced SCCT Versus](https://github.com/Joshhhuaaa/EnhancedSCCTVersus), and builds on [AllyPal's Reloaded Editor](https://github.com/AllyPal/SCCT_Versus_Reloaded_Editor).

## Install

1. Download the ZIP from [Releases](https://github.com/Lumbridge/SCCT_Versus_Reloaded_Editor/releases).
2. Extract it into the folder that contains `SCCT_Versus.exe`.
3. Run `Reloaded_Editor.exe`.

The editor keeps itself up to date: shortly after it starts, it checks the releases and offers a newer version in a window with its release notes and download size: **Install** (it takes effect the next time you start the editor), **Remind me later** (at the next start, tomorrow, in 3 days or in a week) or **Skip this version**. **Help > Check for RE+ Updates...** checks on demand, and **Help > Check for Updates at Startup** turns the automatic check off. After an update, the first start shows that release's notes once; **Help > What's New in RE+...** shows them again. The version an update replaced is kept as `Reloaded.Editor.previous.dll` (with `Reloaded_Editor.previous.exe` when the launcher changed): **Help > Roll Back to RE+ x.y.z...** puts it back at the next start, keeps the newer version to switch forward to again, and stops the startup check offering the version you left (**Check for RE+ Updates...** still can). The window title and **Help > About RE+...** show the version you are running.

### Versions

RE+ releases are numbered `MAJOR.MINOR.PATCH`, starting at **RE+ 2.0.0** (1.x was AllyPal's Reloaded Editor and the 1.3.0 betas that led to RE+):

- **MINOR** (2.1.0, 2.2.0) is a feature release: new tools, windows or workflows.
- **PATCH** (2.1.1) only fixes bugs.
- **MAJOR** changes only when something stops being compatible, such as the install layout or files an earlier version saved.

A release that needs testing first goes out as a release candidate (`2.1.0-rc.1`), marked as a pre-release on GitHub. The updater offers release candidates only to editors already running one, so everyone else gets the release.

Looking for maps to open? Recovered, enhanced and community maps are in [SCCT-Maps](https://github.com/Lumbridge/SCCT-Maps), and [SCCT Map Manager](https://github.com/Lumbridge/SCCT-Map-Manager) installs them for you.

## What it adds

### Map Design workspace

![Map Design workspace](docs/images/map-design.png)

**RE+ Tools > Map Design...** is a floor-plan view for planning and greyboxing a map. Draw rooms, corridors, vents and doorways as parametric pieces and drag, resize or type to change them; the brushes in the map follow every edit in one Undo step. Right-click anywhere for what applies at that point. Copy, paste, duplicate and mirror pieces, pick common sizes from presets, draw sightlines that show where a wall blocks the view, or start from a **Versus starter layout** with spawn rooms, corridors, a vent route, starts, a mission and an objective already placed. It also has reference images, player-size guides, routes timed for spies and mercs, playtest spawns, groups and locks in a Scene panel, a design check, a **Security** window that places lasers, cameras, motion sensors, mines and alarms and wires them together, and lights placed from presets, dragged into reach, and checked for the dark spots spies will use. Full guide: [docs/MapDesign.md](docs/MapDesign.md).

A line's items follow its first belt's **ItemMeshes**, **ItemSpacing**, **ItemScale**, **FadeDistance** and **bShowItems**, and each belt added after another starts with that belt's; in a closed loop the belt whose name sorts first as text counts (ConveyorBelt10 before ConveyorBelt2), so set them alike on all of a loop's belts. The belt's classes, meshes and texture are saved inside the map, so players need nothing extra; every machine runs its own belts and nothing is sent over the network. Below the list, its timing (**MoveTime**, **StayOpenTime**, **DelayTime**, **DelayTimeLastKey**) and what sets it going (**InitialState** in plain words, such as *Triggered: opens, closes after StayOpenTime*, and **bTriggerOnceOnly**), what happens when something is in the way, how it eases, what bumps it, its **Event** and its sounds, changed together with **Apply Settings**. **Wire to This Mover** points a trigger, button, switch or SMagicEvent at it (the trigger's **Event**, or a new action in the SMagicEvent's first group, names the mover's **Tag**; a mover without a Tag of its own gets one named after it), the window lists what triggers it already, **Rename Tag...** renames its Tag with the events that use it, and **Players in Match...** sets the lobby sizes it opens in. The window follows the selection. Every change is one Undo step. Keys hold places and turns only: every leg takes the same **MoveTime**, and a mover holds at most 8 keys. |
| **Light and Shadow Map** | **RE+ Tools > Light and Shadow Map** colours the walkable floor in every level viewport by how lit it is, to show where a spy can hide: **blue** hidden, **yellow** partly visible, **red** exposed (also told apart by the lines: a square, one diagonal, both), with a legend and, in the top view, a readout of the patch under the mouse. The floor is the walkable BSP and the tops of static meshes a player collides with. The 3D view hides patches behind walls; front and side views show the legend only. **Map Design > Tools > Show light and shadow map** draws the same patches on the plan. Brightness (0 to 255) is the brighter of the floor's baked lighting (its lightmap; on a static mesh, the static lights Build Lighting found reaching it) and the in-game and dynamic lights reaching spy chest height, with the engine's own falloff and light effects. Spotlights light only inside their **LightCone**, and the game's shadow-casting spot lights (**LE_ESpotShadow**) only inside their frustum (**EchelonRange**, **SpotWidth**, **SpotHeight**, **NearPlaneRatio**). Lights are blocked by the BSP and by drawn static meshes, except the small fitting a lamp sits in. It is an estimate, not the game's own visibility formula: projectors, movers, zone ambient on static meshes and each actor's four-light limit are left out, and flickering or pulsing lights count at full brightness, so playtest to confirm. It follows edits a moment after they settle, working out again only the lights an edit could change; toggle it off and on (or **Refresh** in **Light and Shadow Settings...**) after a lighting build. **Light and Shadow Settings...** sets the two thresholds, the patch size, the height lights are measured at, which brightness to use, and whether static meshes block light, static mesh floors get patches and spotlight cones are applied; they are kept in `Reloaded_Editor.ini` under `[LightShadowMap]`. |
| **Character Skins** | **RE+ Tools > Character Skins...** dresses the map's spies and mercs in its own materials or models, for example snow camo on a snowy map. **Download Default Skins...** saves the stock textures as 32-bit TGA files (SpyBody, SpyHead, MercBody, MercHead) to a folder you choose, to paint over in Photoshop or any paint program. **Import...** loads an edited image (TGA, BMP, PCX or DDS, sides a power of two) into the map's own package, compressed like the stock texture; **Use Selected** takes the Texture Browser's texture instead. An empty slot keeps the stock look. **Apply** compiles a small script actor into the map itself, so the game and the Reloaded patch are untouched; every machine that loads the map runs its own copy and nothing is sent over the network. Keep the layout of the downloaded textures so the UVs line up: thermal and EMF vision keep the stock heat and EMF masks, and the game's wet, sticky cam and phospho skins still show while they last. A 3D preview beside the fields shows a spy (left) and a merc (right) as they will look, holding a standing pose from their team's animations, and follows the fields as you edit them, before Apply: drag to turn, right-drag or the wheel to zoom, middle-drag to pan, double-click to reset. It does not show the goggle lights, and the map's own viewports still show the stock look; play the map to see the skins in game. **Spy model** and **Merc model** swap a team's whole character model for any loaded skeletal mesh (the stock spy and merc models are listed too); the team keeps its own animations, so moving, stances, the gun and gadgets still work, and a team with a model shows the model's own materials. **Goggle lights X Y Z** moves the spy's or merc's goggle lights along the head bone onto the new head (4, 0, 0 for the merc model on a spy, filled in when you pick it). Picking another model replaces the old model's offset (the one filled in when you picked it, or the one the map has with it, such as a model preset's) with the new model's, or 0, 0, 0 when it has none, and picking the map's own model again brings back the offset the map has with it; an offset you have typed and not yet applied is kept. When the map is played from the editor, the console (`` ` ``) has **addbot** to stand a character of the other team in front of you (a merc holds its gun), so you can see that team's look, and **killbots** to remove them; the console still prints "not a recognised command" after them. Maps made by earlier versions are updated on Apply. **Remove from Map** goes back to the stock characters. |
| **Character Skin Presets** | **RE+ Tools > Character Skin Presets...**, or **Presets...** in the Character Skins window, is a library of skins for one team each: a **spy preset** holds the spy body and head, the spy model swap and its goggle light offset, a **merc preset** the merc ones, so spies and mercs can wear different presets (desert spies against snow mercs). **Spy presets** and **Merc presets** at the top switch between the two lists; inside each, browse by category (Woodland & Jungle, Desert, Snow & Arctic, Urban & Night, Fun and your own) with search, small thumbnails and a large preview of that team's body and head. Below the preview, **On this map now** shows what both teams wear, with their textures and the preset's name. Every built-in look comes as a spy preset and a merc preset: Woodland, Jungle Tiger Stripe, Desert, Arid Digital, Snow, Arctic Digital, Urban Night, Midnight Blue, Team Red, Team Blue, Hazard Stripes, Solid Gold and Bubblegum. They are painted over the stock spy and merc textures when shown or applied, so folds, straps and the UV layout stay, lit lenses, lamps, skin and the merc's orange goggles are kept, and thermal and EMF vision still show the stock masks; nothing but the DLL is needed. **Apply to Spies on This Map** (or **Apply to Mercs**, or double-click the preset; double-clicking a category's name folds or unfolds it instead) imports the preset's pictures into the map and applies it exactly as the Character Skins window's Import and Apply do, changing only that team: the other team keeps what the map gives it. Applying the same preset again reuses the textures it imported. **Save Current Spy Skins as Preset...** (or Merc, following the list shown) keeps that team's values from the Character Skins window as your own preset: textures stored in the map are saved as pictures beside it, other materials and models by name. **Rename...** and **Delete...** change your presets; built-in presets never change, **Hide** takes one out of the list and **Restore Hidden** brings them back. **Export Preset File...** writes a `.skinpreset` file of one preset with its pictures inside to share, and **Import Preset File...** adds one to your presets. Your presets live in `System\ReloadedEditor\skin_presets.json`, with their pictures in `System\ReloadedEditor\skin_presets\<id>`. Presets saved before presets were split by team, which dressed both teams, are split into a spy preset and a merc preset of the same name the first time the window opens (pictures included; the old file is kept as `skin_presets.before-teams.json`), and an older `.skinpreset` file imports as two presets. |
| **Map JSON import/export** | Export a map to JSON, edit it (or have something edit it for you), and import the changes in one Undo step. The import preview lists every actor added, modified (each property, old and new), moved and deleted; click a row to select the actor, and **Apply changes** still goes ahead after rows are selected. ### Map recovery, lighting and sharing

| Tool | What it does |
| --- | --- |
| **Recover Compiled Map** (File menu) | Turns a compiled `.sdc` into an editable map with brushes, actors and extracted meshes. A progress window shows each stage; **Cancel** stops it until saving starts and leaves a new empty map with no files behind. At the end a **Recovery Report** gives brush and polygon counts before and after merging and lists what did not come back cleanly (thin brushes, actors left out, cleared references, meshes or BSP surfaces whose original lighting could not be kept); click a row to select and frame it. The original file is untouched. |
| **Merge Recovered Geometry** (File menu, on by default) | Recovery joins the compiled BSP's fragments into fewer, larger brushes (they may overlap, which leaves the built geometry the same) and combines matching surface pieces. Any merged brush the editor's BSP build does not reproduce exactly is split back automatically. Turn it off to get only the face joining earlier versions did. |
| **Recalculate Selected Lighting** (Build menu) | Re-bakes lighting only for the selected faces, brushes and meshes, keeping the recovered lighting everywhere else. |
| **Match Selected BSP Lighting** (Build menu) | Experimental: blends new BSP faces into the surrounding original lighting. |
| **Lighting Budget** (Build menu) | Lists every zone's lights (static, in-game, dynamic), the most in-game lights reaching one BSP leaf and the largest group of in-game lights that all overlap, measured the way the editor's own **Check InGame / Dynamic Lights** tools do, with the zones and hotspots over budget. Click a row to select its lights, double-click to frame them. Right-click a zone or hotspot (or use the buttons) to **Make Lights Static** (clears the in-game and dynamic flags so Build Lighting bakes them) or **Turn Off the Weakest** N; the window asks first and each fix is one undoable step. **Build All** and the lighting rebuilds warn first when a map is far over budget (**Build anyway / Open Lighting Budget / Cancel**, or don't warn again for that map this session). Limits are in `Reloaded_Editor.ini` under `[LightingBudget]`. |
| **Render Budget** (Build menu) | Per zone: static meshes and their triangles, actors, BSP nodes, surfaces and triangles, unique materials and textures, and emitters, with the zones and single meshes heavier than anything in the shipped Versus maps listed as hotspots. **What Renders From Camera** repaints the perspective viewport and shows the zones it sees through the portals, the actors the engine drew and the totals for that view. Below the zones, switch the list from the hotspots to **Meshes by cost**: one row per static mesh with its copies, the triangles of one and of all of them, and their share of the map's triangles, heaviest first. Click a zone (or the camera's view) above and only what is in it counts, as a share of its own triangles. Click a row to select its actors, double-click to frame them. A mesh row selects the copies it counts: those drawn in game (not hidden) in the map, or in the zone or view clicked above. After editing the map, **Refresh** to count it again. Guidelines are in `Reloaded_Editor.ini` under `[RenderBudget]`. |
| **4 GB for the editor** | The stock editor is a 32-bit program limited to 2 GB, so a big map plus a few large static mesh packages ran out of memory ("ReadFile failed ... Invalid access to memory location" when opening a package; the crash report's "2047MB RAM" is that limit, not your PC). RE+ marks `ChaosTheory_Editor.exe` large address aware, which gives it 4 GB on 64-bit Windows: on the first start with this version it keeps the unchanged editor as `ChaosTheory_Editor.original.exe` and the next start has the room. Only that one header flag changes; the game is not touched. `[Memory] LargeAddressAware=0` in `Reloaded_Editor.ini` turns it off (put the original back by hand to undo it). |
| **Map Check** (Build menu) | Lists what the stock **Check Map for Errors** misses, from the BSP as last built: player starts, pickups and objectives in the void (solid space, outside every zone), far outside the geometry, beyond the world limit, or with their collision cut into BSP or a blocking static mesh (the editor's own spawn test); ZoneInfos in solid space or sharing a zone (two areas joined because a zone portal does not seal its opening, or an opening has no portal), with the leak path from one to the other drawn in the viewports like a pointfile; zones open to the outside of the map; zone portals that seal nothing or left no polygons; and static meshes floating 1 to 48 units above the surface below them (set the range with `FloatingMinGap` and `FloatingMaxGap`; `FloatingMaxGap=0` turns this check off). With two or more floating meshes, one more row above theirs selects them all: click it and press **End** over a viewport to drop them to the floor. A mesh inside the box of a static mesh that does not block (standing on a shelf with its collision off, say) is listed apart as a note, since **End** may drop it through. Flat meshes under 2 units high (decals, puddles) lifted 2 units or less are left out, since they are often raised on purpose to stop flickering. It also lists the static meshes the map uses whose collision the game cannot handle: more than 5,512 collision triangles in either set (the mesh's own per-polygon triangles, or its MCDCX hull triangles), which crashes the game at random places, since the game marks the triangles a trace tests in a fixed table of 5,512 slots without checking the count; a collision BSP at its 32,767-node limit, past which triangles never collide; per-polygon collision cut at the importer's 15,000 triangles; and malformed hulls, with more triangles than 2 x corners - 4, whose faces overlap so the game ignores them and players fall or walk through. A mesh none of whose actors collide is listed as a note. Set the limits with `CollisionTriangleLimit`, `CollisionBspNodeLimit` and `PerPolygonTriangleCap` (0 turns one off), and `MalformedHulls=0` turns the hull check off. The editor keeps a mesh's hulls as one list of triangles, so Map Check finds each hull again from their order and shape. The stock check's own entries are listed too, without its dialog. Click a row to select its actors (for a mesh, every actor that uses it) or portal surfaces, double-click to frame them. Settings are in `Reloaded_Editor.ini` under `[MapCheck]`. |
| **Reachability Map** (Build menu) | Works out where a spy and where a merc can walk from their team's player starts, with the engine's own collision tests on the level as last built (BSP, blocking static meshes and blocking volumes): a grid of 32-unit steps, each tried with the team's collision cylinder (the loaded spy and merc pawn classes' sizes; step height and walkable slope from Map Design's **Movement limits**, else the pawn class), stepping up a step, dropping off any ledge a player survives (spies 1,400 units, mercs 950), crouching through gaps a standing player does not fit (spies 100 high, mercs 136), and lining up with doorways off the grid. The cells are drawn in every level viewport, **green** for both teams, **blue** spies only, **red** mercs only (also told apart by the lines: a square, one diagonal, both), with a legend; **Map Design > Tools > Show reachability map** draws them on the plan. It runs a few steps at a time so the editor stays usable, the cells grow as it goes, and choosing the menu item again cancels it. **Map Check** lists, under *Reachability*, the objectives (SObjectives without triggers, objective triggers, computer terminals, bomb targets, flags and drop zones) the spies cannot get to or the mercs cannot get to (they cannot defend it), as warnings since a climb may be the way there, pickups out of reach for their team, and starts that reach nothing; it starts a run when none fits the map as it is and refreshes when it ends. Ladders, pipes, ledge grabs, zip lines and jumps are not modelled (the only way up is a step), so a place reached only that way shows as out of reach; doors and lifts are left out (doors count as open). Settings (`[Reachability]` in `Reloaded_Editor.ini`): **CellSize**, **MaxCells** (per team; 150,000), **ReachDistance**, **SpyMaxDrop**, **MercMaxDrop**, **RunWithMapCheck**. |
| **Package Map for Sharing** (File menu) | Builds a ZIP of the map with all its dependencies and an install readme. It starts at the open map's release copy (Optimise Map Assets) when it has one. If the map, or its interface package (`<Map>-i`, which Level Snapshot and Minimap rewrite), was saved after the release copy, it shows both dates and asks: **Yes** opens Optimise Map Assets to make a new release copy, which then offers packaging; **No** packages the map from `Packages\Maps` instead; **Cancel** stops. The status line names the map file being packaged and when it was saved. Files identical in the base install players already have (**Base Install...** in Optimise Map Assets) start unticked, and the status line counts them; **Exclude base files...** opens at that folder, and a game folder picked there becomes the new base install, unless its name has letters outside Windows' language for non-Unicode programs: then it is used for that packaging only, and the status line says so. The ZIP can be saved straight to a USB stick or an exFAT or FAT32 drive. |
| **Optimise Map Assets** (File menu) | A map that uses a few meshes or textures from a big pack (a CoD4 or GoldenEye port, say) needs the whole pack shipped with it. This lists every package the map takes assets from, with how many it uses, their size and the whole package's size, and ticks the ones it uses less than half of. Point **Players already have** at a copy of the game as players get it (**Base Install...**, kept in `Reloaded_Editor.ini` under `[MapOptimise]`): packages identical there are marked *players have it*, left unticked and listed last, since they are never shipped. **Create Release Copy** saves the map, then writes a copy under the map's own name (the game needs its four letters and mode letter, such as `ShipD`) into a release folder laid out like the game's, `Releases\<Map>` by default (`Packages\MapsEd`, the playable `Packages\Maps` copy and `Packages\Textures\<Map>-i.utc`), that carries just the assets it uses from the ticked packages, either inside the copy itself (one file to share) or in a package of their own (`<Map>_Assets.usx`, for several maps that share props). The map's interface package (`<Map>-i`: map-selection picture, loading screens, briefing and map settings) is saved and copied with it. Assets keep their pack and group as groups (`MyLevel.COD4_bog.Props.Crate`). The copy's own import table is checked afterwards, and anything it still takes from a ticked package is moved too, so the copy needs none of them. Your working map keeps using the packages, and the packages are not changed. **Show Assets...** lists every asset with its size, and what the map already carries. It then offers Package Map for Sharing, which takes the release folder's files and the rest from the game. Test a release in a separate copy of the game, since installing it over the working one replaces your working map. Assets a script loads only by name are not found. |
| **Export Map to OBJ** (File > Export > Map to OBJ...) | Writes the built level's BSP surfaces and its static meshes (placed, turned and scaled as the actors have them, with their Skins) as `<Map>.obj` and `<Map>.mtl`, with every texture as a PNG in `textures`, for Blender renders or remodelling. **Axes:** the file is Z up and right-handed, like Blender: an Unreal point (X, Y, Z) is written (X, -Y, Z), so the map is not mirrored. In Blender use File > Import > Wavefront (.obj) with **Forward Axis Y** and **Up Axis Z** (the importer's defaults, -Z forward and Y up, would stand the map on its side). **Scale:** 1 Unreal unit = 1 cm by default, written in metres, so ShipD comes in about 230 m across; change the centimetres per unit in the window. Options: static meshes on or off, textures on or off, and **Selection only** (the selected static mesh actors and BSP surfaces). The BSP is one object (`BSP`, plus `BSP_SkyZone` for the sky zone's room so it can be hidden), each static mesh actor an object named after it. BSP polygons stay polygons and face the way their plane does; static mesh normals follow the mesh's smoothing groups. A texture keeps its alpha (as the opacity map too) only when it is a cut-out (`bMasked`) or alpha (`bAlphaTexture`) texture, or a FinalBlend cuts it out: ordinary DXT5 alpha is a specular mask and would make walls see-through. Materials show their base texture (a Shader's Diffuse, a modifier's or Combiner's first material); shader effects, glass opacity, lighting and lightmaps are not exported. Hidden (`bHidden`), invisible, portal and fake-backdrop surfaces and actors are left out, and so are movers' brushes, emitters, terrain and skeletal meshes. Rebuild the geometry first: the export reads the built BSP. ShipD takes about 3 seconds; settings and the folder are kept in `Reloaded_Editor.ini` under `[ObjExport]`, the window's place under `[WindowPlacement]`. File > Export > Map... is the stock Export. |

Recovered maps keep their original baked lighting through ordinary builds. Recovery is experimental: brush history cannot be restored, so check the result in the editor and in game.

| **Open Recent** | **File > Open Recent** lists the last ten maps opened or saved, and warns before discarding unsaved changes: anything you changed since the map was opened or last saved, however you saved it (File > Save, Save As, Ctrl+L). A Save As you cancel, a save that fails (a read-only map), the autosave and a copy saved somewhere else do not count as saving the map. (The editor's own autosave, in Advanced Options, still writes `Auto0` to `Auto9.sdc` into MapsEd every five minutes.) RE+ also keeps the last five saved versions of each map in `System\ReloadedEditor\Backups\<Map>`; **File > Open Map Backup...** opens one (see Crash recovery). Backups and autosaves you open are not added to the list. |
| **Crash recovery** | If the editor crashed, stopped responding and was ended, or was killed, the next start offers to open the newest autosave written during that session, or the map as it was last saved, and names the session's crash report in `System\Diagnostics` if one was written. Autosaves from before that session are never offered. Other editors still running are not mistaken for a crash. **File > Open Latest Autosave...** opens the newest `Auto*.sdc` at any time. An autosave opens under its own name: use **Save As** to keep it. Set `OfferAtStartup=0` under `[CrashRecovery]` in `Reloaded_Editor.ini` to turn the offer off. Before a save replaces a map in MapsEd, RE+ copies the file being replaced to `System\ReloadedEditor\Backups\<Map>`, named after the map and the time it was replaced (`MoonD_20261017_143205.sdc`), and keeps the last five of each map. **File > Open Map Backup...** opens one under its own name. While it is open, **Save** asks where to save, as it does for a new map, so your changes do not go back into the Backups folder unless you choose it; save over the map in MapsEd to restore it (the version it replaces is kept too). A backup saved over the map it was taken from, or an autosave saved over a map, leaves that map's RE+ library entry as it was: its Map Design workspace, Working Views, camera bookmarks and assemblies placed (pieces, views or bookmarks added while the backup or autosave was open stay with that file, not the map). Under `[SaveBackups]` in `Reloaded_Editor.ini`, `Keep` is how many versions of each map stay (`Keep=0` turns backups off) and `MaxTotalMB` (2048) caps all of them together: the oldest go first, never a map's newest. A backup you save your own changes into is listed in `SavedOver.txt` in its folder and is never removed or counted. |
| **Compare with Backup** | **File > Compare with Backup...** shows what differs between the open map and a saved copy of it: one of the backups RE+ keeps (it opens in the map's own backup folder), a stock autosave or any `.sdc`. The copy is read without being opened: it is loaded beside the map under a name of its own and unloaded again, and the map you are editing is not touched. The list shows each actor deleted, added, moved (Location, Rotation) or changed, property by property, with the backup's value beside the map's (an emitter's particle settings included). Click a row to select the actor in the viewports. Tick rows (or **Tick All**) and **Bring Back Selected** puts the backup's version back through the Map JSON import, all in one Undo step: a deleted actor is added again with its old settings (under its old name, or `Name_2` while the deleted one is still kept for Undo), an added actor is deleted, a property or position is set back. Save the map to keep it. Brushes and volumes are compared by their properties only: a changed shape is not listed, and a deleted brush cannot be brought back. Map settings (the LevelInfo), lighting and paths are not compared. |

A place that is no longer on any monitor, after one is unplugged or the resolution changes, is ignored and the window opens where Windows puts it; one that no longer fits on its screen is made to fit. A second Find Usages window opens where Windows puts it, not over the first. |

The picture leaves out what RE+ itself draws over the viewports (the Light and Shadow Map and its legend, measurements, Map Check's leak path, placement previews), and so do the Working Views and Actor Assemblies thumbnails; it all comes back on screen once the picture is taken. |
| **Generate Minimap** | **Build > Generate Minimap...** draws a clean top-down plan of the map from its built geometry, in the stock style (the floor shown in light green, every other floor dark, transparent around the map), with objectives numbered by objective, flags, drop zones, spawns and static meshes as options. **Floors at Z** lists the floors (the map's in-game floors if it has them, else the storeys found in it; type your own and **Apply**); **Show** picks the whole map or one floor, and **Heights** any height range. **Set as the in-game map** makes one 256 x 256 picture per floor in the map's own package (`MyLevel.Minimap.Floor0`, ...) and points the LevelInfo's `MapFloors` and `SnapshotCamera` at them, in one Undo step: in game, the map page shows the floor the player stands on and places the players on it. Save the map to keep it. **Write Briefing to the interface package** puts the picture in the map's `<Map>-i` package as the plan the lobby shows (backed up first, like Level Snapshot). **Save Image...** saves a PNG or TGA at 256, 512 or 1024. **Framing** keeps the play area (spawns and objectives) in view, takes everything built, or keeps the map's current minimap camera. |
| **Map Outliner** | **View > Map Outliner...** (also under **RE+ Tools**) lists every actor in the map with its Name, Class, Group, Tag, Event, location and whether it is hidden or locked (**bLockLocation**). Group the list by class or by the map's **Group** names (an actor in two groups is listed under both; double-click a header, or Left / Right, to fold it), click a column to sort by it, and type in **Search** to keep only the rows with every typed word in some column (`light lobby`, `hidden`). Click a row to select that actor in the editor, Ctrl / Shift for several, a group header for its whole group; double-click, **Enter**, **F** or **Frame** frames them in the viewports. With **Follow selection** on, the list highlights and scrolls to whatever is selected in the viewports. **Hide**, **Show** and **Show All** set the same flags as **RE+: Visibility**, and hidden actors are never selected. **Delete** (the key or the button) asks first and deletes the chosen actors in one Undo step; the level info and the builder brush stay. The list is virtual and reads the map in one pass only when something changed, so a map of thousands of actors stays responsive. |
| **Select and hide** | Right-click an actor for **RE+: Select** (all of this class, all with this Tag, same static mesh, invert the selection) and **RE+: Visibility** (hide selected, isolate selected, unhide all); Brush Visibility has the same three buttons. Security cameras are included; all of this class, all with this Tag and invert never pick hidden actors, so the next Delete or move leaves what you cannot see alone; isolate selected needs a selection; unhide all works on any map size. |

Surfaces already built into the BSP stay, so it reads best in the wireframe views. |

Each view shows a thumbnail of the perspective viewport taken when it was saved or updated; right-click a view for **Update Thumbnail**. Thumbnails live in `System\ReloadedEditor\thumbnails`, named after the view's id, so renaming keeps them and deleting removes them. Views saved before thumbnails existed show a placeholder until updated. **Camera bookmarks** for getting around big maps: **Ctrl+1** to **Ctrl+9** over a viewport stores the viewport cameras as bookmark 1 to 9 of the open map, and **1** to **9** jumps straight back (a number with no bookmark beeps). Bookmarks are listed in Working Views as Bookmark 1, Bookmark 2 and so on, with their key after the viewport count, and can be renamed, updated or deleted there like any view; going back to one puts each viewport's camera, zoom, view mode and show flags back as they were, leaving hidden actors and groups as they are. **RE+ Tools > Camera Bookmarks** has the same choices. |
| **Actor Assemblies** | Save groups of actors and brushes and reuse them across maps. Each assembly shows a thumbnail taken when it is saved, with the perspective camera briefly moved to frame the selection and then put back exactly; right-click for **Update Thumbnail**, which frames the current selection (or takes the viewport as it is when nothing is selected). **Place Linked...** places a copy that stays linked to its assembly as a prefab: edit any linked copy, select one of its actors and choose **Update Prefab from This Instance...** (in the window, on the actor's right-click menu or under **RE+ Tools > Linked Prefabs**), and that copy becomes the assembly's content while every other linked copy in the map is rebuilt where it now stands, keeping its own position and rotation, in one Undo step. Tags the copies' Events use get fresh names in each copy, as they do for any placement. **Select Instance**, **Select All Instances** and **Break Link** (the copy's actors stay as ordinary actors) are in the same places, and the list shows how many linked copies of each assembly the open map has. A copy is its actors' Group (`Prefab_<name>_<id>`, saved in the map) plus its record in the RE+ library, so the link survives save and reopen; put an actor in that Group to make it part of the copy. Undo puts the map back but the library keeps the new content. Every rebuilt copy points at the same outside actors as the edited one; copies placed before linking, with **Place...**, and other maps are never changed. A prefab with brushes needs a geometry rebuild to show their new shape. |
| **Emitter Library** | **RE+ Tools > Emitter Library...** browses particle effects by category with search and a live, engine-rendered preview (drag to orbit, wheel to zoom). **Place at builder brush** (or double-click) adds the effect in one Undo step. Tick **Loop** to place any effect, triggered ones included, so it plays again on its own a random wait of your chosen seconds after it ends. Ships with 37 effects captured from the stock maps: fire with smoke, torches, steam, drips, splashes, bubbles, rain, snow, sparks, dust, moths and triggered bursts. Select emitters and right-click **Save to Emitter Library...** to add your own; read-only effect packs in `System\ReloadedEditor\EmitterPacks` appear as their own group. **Edit effect...** opens an edit panel for each particle system of the selected effect: particle count, rate and initial rate, lifetime, size and height, velocity, acceleration, texture (typed, or **Use texture browser selection**), a tint and its colours over life (colour picker). Each change shows in the preview at once, and values are checked (ordered ranges, capped counts and rates). **Revert** restores the effect's values, **Save as New Effect...** keeps a copy under Your effects and **Save** updates one of your own; built-in and pack effects never change, and **Place** puts the edited version in the map. |
| **Undo History** | **Edit > Undo History...** lists every step in the editor's undo buffer, oldest at the top, with the steps waiting for Redo greyed below the current one, and how much of the buffer's memory they use. Double-click a step to undo or redo, one stock step at a time, until the map is as it was after it; the list follows every edit, map load and buffer reset. **Add checkpoint...** (or **Edit > Add Undo Checkpoint...**) names the current step, such as "before vent rework"; right-click a step to name it instead, rename or remove a checkpoint (Delete also removes). Checkpoints show as tags in the list, and the jump list above it undoes or redoes straight to one. A checkpoint lasts while its step is in the undo buffer: it goes when the full buffer drops the step, when a new edit replaces the undone steps it was on, or when a map load clears the history. |
| **Animation Browser** | **View > Show Animation Browser** browses skeletal meshes, animation sets, sequences and notifies, and imports `.psk`/`.psa` files. Importing a `.psa` into an existing set honours the import options: **Merge sequences into existing** adds the file's new sequences and keeps the rest (the skeleton must match bone for bone, or nothing changes), **Overwrite existing sequences** also replaces same-named ones, and **Keep Notifies** carries a replaced sequence's notifies onto its new version. Without Merge the file replaces the whole set, after a confirmation. The set stays the same object, so meshes using it stay linked; nothing is undoable, so save once you are happy. Standard ActorX `.psa` files import too (the stock editor crashed on them). Deleting a sequence (right-click > **Delete**) asks first, keeps the other sequences' motion and marks the package for saving; renames refuse names already used in the set, and names with anything but letters, digits, `_` and `-`. |
| **Find Usages** | Find where a texture or mesh is used in the open map, and replace it. Unchecked usages stay unchecked while you select actors or edit the map, until you press **Refresh** or change **Limit to selection captured at Refresh**; that box keeps to the actors and BSP surfaces that were selected when you last did either. Saving the map under a new name keeps the check boxes. A usage that becomes read-only is unchecked, and one that becomes replaceable is checked as it would have been at the last **Refresh**, unless you had unchecked it. Usages that appear since come in checked when replaceable, or unchecked while the box is ticked; one you had unchecked that left the list (its asset changed, or its actor deleted) comes back unchecked, for example after Undo. A geometry build or brush CSG operation renumbers the BSP surfaces, so their rows come in the same way, or all unchecked if you had unchecked a replaceable one (a read-only one stays unchecked once it becomes replaceable), and the status line says so until you press **Refresh** or change the box. **Find Usages in All Maps...** (right-click a texture or static mesh in its browser, or **Search All Maps...** in the Find Usages window) lists every map in MapsEd that uses it, optionally the game's Maps folder too, before you change a shared package. | **Static Mesh Browser search** | Type in the **Search** box under the Static Mesh Browser's list and the list filters as soon as you pause: every word must appear somewhere in *package.group.name* or its English, case ignored, so *door metal* finds Porte_Metal01. | **Import OBJ** | **File > Import OBJ...** in the Static Mesh Browser (or **File > Import OBJ Mesh...** in the editor) makes a static mesh from a Wavefront `.obj` file, as exported by Blender, Maya, 3ds Max and most modelling programs. Pick the file, the **Package** (`MyLevel`, the default, keeps the mesh inside the map, so it ships with it), **Group** and **Name**, the **Scale** (Unreal units per OBJ unit: 1 makes one OBJ unit 1 unit, about 1 cm) and whether the file is **Y up** (Blender's and most exporters' default) or **Z up**. The box under the options shows what the import will make before anything changes: triangles, size, collision, where each material comes from and whether it needs parts. **Materials** come from the `.mtl` file beside it: a loaded material with the material's name is used as it is (so a second import, or one made with stock texture names, reuses them); otherwise its `map_Kd` image is imported into the package's `Textures` group (TGA, BMP, PCX and DDS with sides a power of two as they are; PNG, JPG and others scaled to the nearest power of two, at most 2048, and compressed DXT1, or DXT5 when they have transparency); a material with neither gets the default texture. **Collision**: convex hulls, one per connected part (the default) or one per OBJ object or group, built from the mesh and made clean (flat faces and one face per set of corners, which the game needs or it ignores the hull; a hull is kept to 128 corners, and a flat part such as a sign or a floor gets a hull 2 units thick behind it); hulls from the file's own objects named `UCX_` or `MCD` (never drawn); a simple box; the mesh's own triangles (per polygon); or none. The game crashes on a mesh with more than 5,512 collision triangles, of its own or in its hulls, so **Split into parts** cuts a bigger mesh into parts that each keep within it (`Name`, `Name_2`, ...); they share the pivot, so placed at the same place and rotation they make the whole. If a part's collision tree still reaches the editor's 32,767-node cap, the parts are made again smaller. **Place in the map** puts the mesh, or every part, where the viewport was last clicked, in one Undo step. The import itself is not undoable: delete the meshes in the browser, and save the map (MyLevel) or the package to keep them. Normals are not read: shading follows the file's smoothing groups (`s`). |

| **Scatter Props** | **RE+ Tools > Scatter Props...** fills a room with clutter. <summary>Build from source</summary>

Use a Visual Studio C++ developer PowerShell with the v143 toolset and the manifest's vcpkg dependencies installed:

```powershell
$env:SCCT = $null # Skip deployment into an installed game.
msbuild SCCT_Versus_Reloaded_Editor.sln /m /t:Rebuild /p:Configuration=Release /p:Platform=x86 /p:PlatformToolset=v143
if ($LASTEXITCODE -ne 0) { throw 'Release build failed' }
./tools/package_release.ps1
```

Set the version in `Reloaded.Editor/Version.h` first: the title, About box, updater, DLL properties and archive name all come from it. The release ZIP is written to `bin/Reloaded_Editor_Plus_v<version>.zip`; tag the release `v<version>`. Packaging downloads the unchanged AllyPal v1.2 launcher and verifies its hash; pass `-LauncherPath` to use a local copy. Tests are described in [tests/README.md](tests/README.md).
